route, shape or command that changed (old form, new form), a step skipped or not completed, a dependency

- Task 12, inactivity limit (ACC-04), a convention the plan did not have, for plans 01b and 05: a view whose route a page calls on a timer declares `background = True` on the view class, beside `access` and `http_method_names`. Without the attribute a call counts as activity. `apps.accounts.middleware.InactivityMiddleware` reads it: a background call is still checked against the limit (past it, the session is ended and the call answers 401), but it never pushes the limit back. Marked in 01a: `UnreadCountView` (`notifications:unread-count`) and `StatusView` (`core:admin-status`). What plan 01b will see: opening the Status page alone is not activity, and a page left untouched for two hours gets 401 from its next poll, which sends it to Sign in. The middleware now works in `process_view`, so it runs only for an address that resolves to a view.
- Task 14, account administration: `create_account`, `assign_role`, `remove_role`, `disable_account` and `enable_account` start by taking a PostgreSQL advisory lock that lasts until their transaction ends (`pg_advisory_xact_lock`, key `apps.accounts.services.administration.ADMINISTRATION_LOCK`), so that two changes at the same moment cannot both pass the "HR never with System Administrator" and "last active administrator" checks. Signatures are unchanged. A service of a later plan that calls one of them (plan 02's archiving calls `disable_account`) holds the lock until its own transaction ends; a plan that adds another advisory lock uses a different key.
- Task 8, `test_the_table_cannot_be_emptied`: re-enabling a disabled trigger inside a test needs `connection.check_constraints()` first, or PostgreSQL refuses the `ALTER TABLE` with "pending trigger events" (the rows the test inserted leave deferred foreign-key checks waiting). Plan 04's ledger test needs the same call.
